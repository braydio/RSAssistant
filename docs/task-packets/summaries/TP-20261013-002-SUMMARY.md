## Limitations
- Breaking change for anyone relying on the old behavior: an enabled watcher with a non-`codex` command, extra flags, empty `AUTO_RSA_DIR`, or no primary channel now stays inert. Watcher is still off by default.
- Redaction is pattern-based best effort; the Discord status deliberately contains no Codex prose at all, so the fixtures prove the status can't leak, not that every pattern is caught.
- stdout/stderr are buffered in memory until the child exits (no output cap); process-group kill is POSIX-only (falls back to `kill()`).
- Error text is redacted before being sent to Codex, but Codex itself is an external service.
- Did not touch global logging (TP-20261010-005 owns it).
